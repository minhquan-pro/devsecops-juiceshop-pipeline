# ERROR ANALYSIS & FAILURE MODES OF JUICESEC ANALYZER

## 1. Overview & Evaluation Methodology

Academic credibility demands rigorous examination of scanner failures rather than presenting artificially inflated perfection. This document details the diagnostic evaluation of the JuiceSec static analysis engine (`juicesec.astscan` and `juicesec.core`), breaking down:
1. **Per-Rule Confusion Matrices** across categorized vulnerabilities (`SQLI`, `XSS`, `IDOR/BAC`, `JWT`, `MISC`).
2. **Four Structural Failure Modes** inherent to lightweight intra-file syntactic and token-based dataflow analysis.
3. **Traceability to Program Analysis Literature** explaining why these failure modes occur and how next-generation engines mitigate them.

The automated artifact generated by [`labs/gen_error_analysis.py`](labs/gen_error_analysis.py) is permanently recorded in [`evidence/error_analysis.json`](evidence/error_analysis.json).

## 3. The Four Structural Failure Modes

### 3.1 Failure Mode 1: Lexical Shadowing & Variable Aliasing (False Positive)
- **Mechanism:** In modern JavaScript/TypeScript, variable declarations in nested block scopes (`{ ... }`) shadow outer identifiers. When an outer variable holds untrusted input (e.g. `req.query.data`) and an inner block re-declares the same variable name with a sanitized value, a token- or flat symbol-table scanner attributes the tainted status to the inner variable.
- **Concrete Code Pattern:**
```javascript
function handleRequest(req, res) {
    const input = req.query.data; // Tainted outer symbol
    if (isValid(input)) {
        const input = sanitizeText(req.query.data); // Shadowed clean symbol
        res.send('<div>' + input + '</div>'); // Safe sink execution
    }
}
```
- **Root Cause in `juicesec/astscan.py`:** The JavaScript heuristic tracking extracts assignment pairs via token scanning rather than building a hierarchical Lexical Scope Environment (Symbol Table Stack).
- **Academic Remedy:** Construct an explicit Static Single Assignment (SSA) form or Lexical Scope Tree where identifiers are keyed by `(name, scope_depth, scope_id)`.

---

### 3.2 Failure Mode 2: Safe Constant Literal Concatenation (False Positive)
- **Mechanism:** String concatenation via binary operator (`+`) or template literals (`${...}`) is flagged as potential SQLi or Command Injection, even when all components are compile-time constants.
- **Concrete Code Pattern:**
```javascript
const TABLE = 'products';
const DEFAULT_FILTER = 'WHERE active = 1';
const sql = 'SELECT * FROM ' + TABLE + ' ' + DEFAULT_FILTER;
db.query(sql); // Safe: only static string constants concatenated
```
- **Root Cause in `juicesec/astscan.py`:** The AST visitor detects binary operations on string nodes containing SQL keywords (`SELECT`) and assumes dynamic composition without performing constant folding or checking operand provenance.
- **Academic Remedy:** Abstract Interpretation over string lattices or compile-time Constant Folding: evaluate constant expressions prior to taint analysis.

---

### 3.3 Failure Mode 3: Dynamic Property Dispatch & Indirect Call (False Negative)
- **Mechanism:** JavaScript supports dynamic property access (`obj[computedKey](args)`) and first-class function passing (callbacks, higher-order functions). Tainted inputs passed into dynamically resolved sinks bypass syntactic call matches.
- **Concrete Code Pattern:**
```javascript
const sinks = { render: (data) => element.innerHTML = data };
const action = req.query.action || 'render';
sinks[action](req.query.payload); // Dynamic dispatch bypassing static AST CallExpression
```
- **Root Cause in `juicesec/astscan.py`:** Syntactic pattern matching expects explicit AST nodes such as `MemberExpression[property.name='innerHTML']`. Computed access with variable keys (`sinks[action]`) is opaque to static name lookups.
- **Academic Remedy:** Points-to analysis (Andersen's or Steensgaard's formulation) combined with dynamic property value set analysis.

---

### 3.4 Failure Mode 4: Inter-procedural & Cross-Module Taint Dissipation (False Negative)
- **Mechanism:** Real-world enterprise applications separate controller routing, service layers, and database queries across distinct files and functions. Intra-procedural/intra-file analysis cannot follow taint across function calls or module imports.
- **Concrete Code Pattern:**
```javascript
// controller.js
const UserService = require('./services/userService');
app.get('/user', (req, res) => {
    UserService.findUserRaw(req.query.id); // Tainted argument passed into module
});

// services/userService.js
class UserService {
    static findUserRaw(id) {
        return db.query('SELECT * FROM users WHERE id = ' + id); // Sink reached here
    }
}
```
- **Root Cause in `juicesec/astscan.py` (v1.1):** The scanner processed AST nodes with local intra-procedural reset at function boundaries.
- **JuiceSec v1.2 Mitigation:** Implemented a two-pass Inter-procedural Call Graph and Function Summaries tracker for Python:
  1. *Pass 1:* Traverses all `FunctionDef` and `AsyncFunctionDef` nodes to build call graphs and summaries recording parameter indices, calls, return taint status, and sink proximity.
  2. *Pass 2:* Propagates taint across multi-hop calls (`entry -> mid -> sink`), function return values (`res = tainted_source()`), and class methods. This directly boosted out-of-sample CVE validation F1 from **0.5625** to **0.6471**.
- **Remaining Open Boundary:** Cross-module external package imports and dynamic JavaScript module resolution across separate `.js` files.

## 4. Machine Learning Error Analysis (5,000 Synthetic Sample Benchmark)

### 4.2 Error Breakdown & Failure Modes in ML

1. **MLP False Negatives on Subtle Polyglot Mutations:**
   - The neural network (MLP) relies on linear projections of the 53 engineered features. Without explicit tree-depth partitioning, non-linear interactions (e.g., high entropy + indirect sink + missing sanitizer) produce lower activation in fold tests, resulting in 17.16% false negatives.
2. **Ensemble False Positives on High-Entropy Benign Payloads:**
   - The ensemble occasionally flags benign code snippets containing complex regular expressions, cryptographic hashes, or math constants as high risk due to elevated Shannon entropy feature weights.
3. **Architectural Mitigation:**
   - The system utilizes an **Asymmetric Risk Gate**: AST deterministic rules handle hard ground truth, while the calibrated ensemble handles contextual triage. Critical and High AST findings cannot be suppressed by ML confidence errors.
